# Claude Code on the BUSY Bar: the bar app

The app for the BUSY Bar, id `app.mrlunev.claude_code`. It long-polls the local server that the `busybar` Claude Code
plugin runs on the computer, shows the computer's Claude Code sessions on the front display, and sends the answers to
permission prompts back. To install it with the plugin, see the
[main README](https://github.com/mrlunev/busybar-claude-code#readme).

## Screens

- **Session list**: two rows at a time, each with the session's state, project name and task time. The wheel moves
  the cursor, Start or the wheel press opens a session, Back closes the app.
- **Session**: what Claude is doing, the timer and the project name; with the Context bar setting on, the frame's
  bottom edge shows how full the context window is. Back returns to the list.
- **Approve?** followed by the command: a permission prompt. The LED blinks, the wheel picks Yes (left) or No
  (right), Start or the wheel press sends it, Back hands it back to the terminal. `+N` counts the prompts behind it.
  A prompt takes no answer until it has been on the screen for 0.4 s.

Messages, first line and second line:

| On the bar | Meaning |
| --- | --- |
| `Needs setup`, `look at the back` | The app has no token yet, for example when installed from the BUSY Apps catalog. The back display says where to open the bar's web page. |
| `Connecting`, the computer's address | Trying to reach the computer. |
| `No computer`, the computer's address | No address answered several times in a row. |
| `Wrong token`, `run setup again` | The computer refused the token. |
| `Not paired`, `run setup` | The computer does not know this bar. |
| `Update app`, `run setup` | The computer's server is newer than this app. |
| `Connected`, `no sessions yet` | Connected; no Claude Code session is running. |

## Settings

In the bar's web page, Apps, Claude Code. Setup fills in `Computer` (one or more `address:port`, comma-separated, tried
in order) and `Token`. The app reads its settings only when it starts.

## Build

Node 24.

```
npm ci
npm run typecheck
npm run build      # dist/app.mrlunev.claude_code.tgz
```

`npm run release` also copies the package to `../plugin/release/`, where setup takes it from. On a disk without
extended attributes (exFAT) macOS adds `._*` files that end up in the package; build with `COPYFILE_DISABLE=1` on an
APFS disk and check the package with `tar -tzf`.

## Source

- `src/main.ts`: the whole app.
- `src/help.ts`: the back display while nothing is set up.
- `shared/device.ts`: a thin `fetch` client for the bar's API.
- `src/appmeta/`: manifest, settings and icons; `src/images/` and `src/animations/` are generated by `npm run images`.
